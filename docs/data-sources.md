Hashes apply to the exact files stored in `data/raw/`, **after decompression** for SOFT files. Downloads are bounded in size and fail on a changed hash. Raw files and the run-specific retrieval log are ignored by Git. Derived outputs can be regenerated with the documented commands.

## Variant-reference and prediction provenance

[config/reference-sources.json](../config/reference-sources.json) pins 27 additional responses. Ensembl release 116 provides variant mappings on both builds, individual reference bases, and genes overlapping fixed 1-Mb neighborhoods. Build-38 reference bases were also retrieved directly from AlphaGenome's GRCh38.p13 FASTA using its `.fai` index and exact HTTP byte ranges. Both the index and the one-base responses have recorded hashes. All alternative mappings remain in raw inputs; ambiguous primary mappings are rejected by the normalizer.

The variant table distinguishes published risk labels from reference/alternate alleles. Candidate-gene tables are derived from the pinned gene annotations. The [run provenance](../reports/pilot-run-provenance.json) records client commit, selected model version, protocol/input hashes, metadata hash, request dates and prediction-file hashes. AlphaGenome access and outputs have [separate terms documented by the official project](https://github.com/google-deepmind/alphagenome#terms). The current work is noncommercial research. Do not assume a future code license would override source-data or model-output conditions.

## Mechanism follow-up sources

[mechanism-sources.json](../config/mechanism-sources.json) pins article XML/HTML, the 2020 Goode thesis, GWAS Catalog study/association metadata, and Ensembl transcript/variant context. Where Europe PMC did not expose XML, the public PMC HTML was used. No browser challenge was treated as article content. The thesis's relevant allele passages on pages 60 and 80 were rendered and visually checked.

[association-sources.json](../config/association-sources.json) pins the original GWAS file header, directory metadata, 23 small byte ranges and rs313839 population frequencies. `fetch_gwas_audit_rows.py` verifies sorted complete interior lines, skips partial boundary fragments and requires an exact rsID/coordinate match. The two selected lines are copied without changing their original fields. `build_allele_audit.py` verifies those copies against pinned ranges and derives separate reviewed fields. The 662,022,204-byte file is not downloaded in full. Its header defines `allele_1` as risk; sample scope and conflicting source labels are described in the audit.

[splice-audit-sources.json](../config/splice-audit-sources.json) pins the official model's coordinate implementation to research-code commit `0db53bd4352c66d1e00a049a81da373a066e6670` and the 2020 Mucaki splicing paper. This code was read to confirm coordinates; it was not used to run a different model. The API client remains pinned separately.

The one additional model request has [separate provenance](../reports/splice-followup-provenance.json). Its original v0.1 protocol is archived unchanged; v0.2 records the post-request donor-index correction. Complete output arrays, native junction coordinates and metadata are saved locally with hashes. Summary joins use feature coordinates and assay identities rather than row order; unreturned features remain missing. The downstream donor is the largest positive change within the originally fixed 101-base window, selected for exploratory interpretation. It is not an independently chosen validation endpoint.

## Full fine-mapping archive and prospective comparison

The September 12 [fine-mapping manifest](../config/finemap-sources.json) pins 43 public sources, including the 16,716,205-byte archive from [Zenodo 11143561](https://zenodo.org/records/11143561), its record metadata, FINEMAP and AlphaGenome documentation, nine rsIDs' mappings on both Ensembl builds, six substitutions' reference bases on both builds and the model FASTA, and reused release/index metadata. The archive's publisher MD5 is `35319e93d376e80958b3c78ae92c1fe5`; its SHA-256 is recorded in the manifest. Zenodo identifies its license as CC BY 4.0. Attribution is to Goode et al. (2024); the new tables change format and add clearly separate audit calculations. Reference services and documentation retain their own terms.

`audit_finemap_archive.py` reads every regular archive member without extracting paths, checks all 26 SNP/configuration/log triplets, and preserves all 71,083 variant rows in a deterministic gzip CSV. Its configuration sums are separate from the original four-decimal PIPs. It compares the saved posterior distribution over causal counts with the logs and reconstructs cumulative sets only for complete singleton-only configurations. The [report](../reports/psc-finemap-and-comparison.md) documents the discrepancies and missing original inputs; the resulting tables are not complete signal-specific credible sets or normalized genotype inputs.

`prepare_controlled_comparison.py` applies the [fixed protocol](../config/psc-controlled-comparison.json), checks the six unambiguous substitutions against the pinned Ensembl 116 and GRCh38.p13 references, and accounts for all 12 high-PIP source records at the selected regions. Five are nominated for matching, one is a reserve and six are excluded. All risk directions remain unspecified. The [freeze record](../config/psc-controlled-comparison-lock.json) pins the protocol and current inputs; future comparator data should use a separate source manifest. Frequencies, LD, matched comparator identities and the common gene/track universe have not yet been prepared. No new model inference or researcher contact occurred in this phase.

## Completed comparator preparation and model run

The later [comparison manifest](../config/psc-comparator-sources.json) adds 85 pinned response records without changing the preceding 43-source manifest. It records complete request bodies and retrieval times for 64 Ensembl bulk-variation requests covering all 6,117 low-PIP rsIDs on both GRCh37 and GRCh38, plus Ensembl 116 gene annotations/release metadata, population indexes/panel, reference sequences and model annotation/implementation. The [Ensembl API](https://rest.ensembl.org/documentation/info/variation_post) documents the 200-ID batch limit. Canonical replacements under a different response key are not silently joined to the original source rsID; raw responses preserve them for future explicit alias review. The mapping audit distinguishes all exclusions.

The [1000 Genomes phase 3 collection](https://www.internationalgenome.org/data-portal/data-collection/phase3/) provides the public release 20130502 sample panel and chromosome 2, 6 and 10 genotype archives. Three bounded indexed queries retain only exact GRCh37 coordinate/REF/ALT matches from the target list; no complete chromosome file is downloaded. The [query record](../config/psc-comparator-genotype-queries.json) pins each index, target/plan hashes, pysam version, sample-bearing VCF subset and its uncompressed content. The raw subsets contain all 2,504 sample columns; matching uses only the panel's 503 EUR donors. Genotype records are joined by coordinates, alleles and donor identities, not VCF row order or rsID alone. All 541 targets are reference-verified, and 540 have exact genotype records. Donor-level inputs remain ignored; frequencies and LD summaries are versioned.

The model [GENCODE v46 annotation](https://storage.googleapis.com/alphagenome/reference/gencode/hg38/gencode.v46.annotation.gtf.gz.feather) is 333,040,258 bytes, read as an Arrow IPC file. Its transcript TSS membership follows the source-pinned official extractor, including its negative-strand exclusive-End point query. The final gene universe intersects this coverage with Ensembl gene-level TSSs inside each fixed interval. That intersection is used for both nearest-TSS matching covariates and scoring, before predictions. Two implementation files are pinned to research-code commit `0db53bd4352c66d1e00a049a81da373a066e6670`; they were read for semantics, not executed as a replacement model.

The [RNA metadata record](../config/psc-comparator-model-metadata.json) separately pins an AlphaGenome metadata RPC response with 667 track rows. Its three `CL:0000624` rows represent plus/minus total RNA and unstranded polyA RNA; stranded merging yields two fixed primary tracks. `fetch_comparison_metadata.py` verifies the cache or retrieves metadata without making variant predictions, and rejects a changed hash. The final [input lock](../config/psc-matched-comparison-inputs.json) pins matching covariates, algorithms, windows, genes and track identities. It was saved before any of the nine requests.

The [model run provenance](../reports/matched-comparison-run-provenance.json) records request times, pinned client, `ALL_FOLDS` selection, runner hash and each prediction-file hash. The service does not expose a server model build identifier through this client. Compact results retain all 228 variant–gene pairs and 456 primary scores; full prediction tables stay ignored. The [summary record](../reports/matched-comparison-summary.json) additionally pins the reporting script. Gene-mask scores are natural-log differences with a 0.001 pseudocount, as documented by the [official implementation](https://github.com/google-deepmind/alphagenome_research/blob/0db53bd4352c66d1e00a049a81da373a066e6670/src/alphagenome_research/model/variant_scoring/gene_mask.py). Source-data and model-output terms remain separate; this work does not relicense them. See [the complete findings and limitations](../reports/matched-comparison.md).
