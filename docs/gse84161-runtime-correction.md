# GSE84161 same-version runtime correction

Execution [plan v3](../config/gse84161-normalization-plan-v3.json) passed source checks, read all 30 CEL files and wrote the raw perfect-match summary, then stopped during RMA background correction with `ERROR; return code from pthread_create() is 22`. It produced no normalized expression matrix. The same error occurred on a synthetic 200-by-3 matrix when calling `preprocessCore::rma.background.correct`, including with `R_THREADS=1`. This isolates the observed failure from the study's biological data; the underlying operating-system cause was not established.

The runtime repair rebuilds the same official `preprocessCore` 1.68.0 source with `--disable-threading` in the separate GSE84161 environment. It does not replace RMA with another algorithm or change its parameters, arrays, annotation or aggregation. The original base runtime manifest and package lock are retained. The supplemental build manifest records the source URL/hash, build flags and resulting installed files; the effective [execution plan](../config/gse84161-normalization-plan.json) pins those files before restarting.

A synthetic background-correction and quantile-normalization check passed in the repaired environment before the study rerun. This smoke check establishes executable library functions, not numerical equivalence with an unavailable successful threaded run. The actual run's full matrices and independently recomputed summaries provide the subsequent numerical checks. See the [runtime reproduction instructions](gse84161-runtime-reproduction.md) for the build steps and dependencies.

The upstream [preprocessCore changelog](https://github.com/bmbolstad/preprocessCore/blob/devel/CHANGELOG) documents threaded implementations and `R_THREADS` control. The local same-version source and build record, rather than that moving branch, define the executed implementation. Prior failed execution logs remain in ignored workspace storage; the frozen plan records their hashes.
